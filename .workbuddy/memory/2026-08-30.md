## Kuikly 页面注册机制（已验证）
- `@Page("xxx")` 标注页面类 → KSP 插件 `core-ksp` 在编译期生成 `KuiklyCoreEntry.kt`（位于 `shared/build/generated/ksp/.../com/tencent/kuikly/core/android/`，属于 `:shared` 模块、但包名不同）。
- 生成代码直接 `BridgeManager.registerPageRouter("router") { com.elyric.lcwhale.RouterPage() }`；框架首次 `callKotlinMethod` 时 `triggerRegisterPages()` 注册，运行时按 pageName 查表构造实例。
- 因此页面类至少是 `internal`（同模块、跨包可见）；`private` 会让生成代码编不过，`public` 会不必要地暴露到 `:shared` 公开 API。这就是 `BasePager`/`RouterPage` 标 `internal` 的原因。

## Kuikly 路由注册机制深挖（反编译 core-ksp / core-render-android 验证）
- 注册链路：`@Page` → KSP `CoreProcessor`（core-ksp jar 经 ServiceLoader 注册 `KuiklyCoreProcessorProvider`）编译期 `getSymbolsWithAnnotation("com.tencent.kuikly.core.annotations.Page")` 扫描 → KotlinPoet 生成 `KuiklyCoreEntry.kt`（固定包名 `com.tencent.kuikly.core.android`；按 target 分 Android/IOS/JS/OhOs EntryBuilder）→ 运行时 core-render-android 的 `KuiklyRenderJvmContextHandler` 按固定类名反射实例化入口 → 首次 `callKotlinMethod` 触发 `triggerRegisterPages()` 填 `BridgeManager` 路由表。
- KSP 扫描不看可见性：core-ksp jar 内无任何 visibility 过滤，filter 仅为 `filterIsInstance<KSClassDeclaration>`；可见性只约束「生成代码 new 页面类」这一步 → `internal` 是下限。
- core-ksp options：`pageName`（分包构建时过滤页面）、`enableMultiModule`（多模块/分包，走 `submodule/*MultiEntryBuilder`）。
- 字节码验证：`internal class RouterPage` 编译后是 `public final class`（internal 仅存于 @Metadata）；`KuiklyCoreEntry` 直接 `invokespecial RouterPage.<init>` 调构造器——页面实例化连反射都不是，只有查找入口类那一步用反射。internal 是编译期模块边界，非运行时安全边界。
